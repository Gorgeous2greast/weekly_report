#  Agentic RL 动态检索奖励优化专项调研 - 2026-11-02

## 🧠 核心研究范式 (Core Paradigms)

### 保真度分层的查询重写奖励：从偏好到严格验证
将人类反馈按反映个性化意图的直接程度分层，先进行示范学习，再用后续消费反馈做相对偏好优化，最后用严格目标一致性奖励约束意图漂移。该范式直接面向查询重写这一检索前置动作。

#### 📄 [WeFair: Fidelity-Aware Alignment from Human Feedback for Personalized Query Rewriting in Short-Video Search](https://huggingface.co/papers/2610.16927)
- **奖励设计**: 摘要显示：偏好阶段用DPO从后续消费反馈学习相对偏好；验证阶段用GRPO奖励与重写或保留目标的精确一致，以约束意图漂移；分析发现严格验证优于辅助奖励。
- **💡 启发**: 对动态检索中的查询重写，可把精确保持用户即时意图或改写目标一致性设为高权重验证奖励，消费或参与偏好仅作低权重辅助，防止检索被参与度信号带偏。

---

### LLM-as-a-Judge的密集过程奖励与终端奖励结合
在线Agent训练中，用LLM裁判给每一步中间进展提供密集反馈，同时以任务完成作为终端奖励，并用步级优势估计优化策略。该范式强调过程奖励与结果奖励的结合。

#### 📄 [Online Dense Reinforcement Learning with Planning-Grounding Agent for UI Navigation on Live IOS Apps](https://huggingface.co/papers/2610.39264)
- **奖励设计**: 摘要显示：LLM-as-a-Judge综合奖励信号，包含评估中间进展的稠密步级反馈和整体任务完成的终端奖励；用PPO与步级优势估计，GiGPPO利用并发轨迹中视觉相似状态的奖励信号改善critic稳定性。
- **💡 启发**: 动态检索可为每次检索或重写动作引入judge的步级进展奖励，并保留终端任务完成奖励；同时可借鉴邻居状态价值估计，对相似检索状态共享价值信号以稳定credit assignment。

---

### 信息增益RL与一致性证书式按需决策
用无真值的信息增益奖励自演化推理，或用无图像预测与图像条件预测的一致性证书决定何时处理视觉信息，体现按需获取外部信息的动态门控思想。该范式可迁移到何时检索、检索多少的动态动作空间设计。

#### 📄 [Latent Reasoning in Continuous Space for Unified Multimodal Models](https://huggingface.co/papers/2610.42149)
- **奖励设计**: 摘要显示：信息增益RL阶段在无ground truth监督下自演化潜在推理；摘要未给出具体信息增益公式。
- **💡 启发**: 可将检索动作的内在奖励设为信息增益，减少对无真值监督的依赖；但需与终端可验证奖励结合，防止仅优化信息增益导致奖励漂移。

#### 📄 [Look Only When Needed: Certificate-Guided Visual Routing for Efficient Diffusion VLMs](https://huggingface.co/papers/2610.36671)
- **奖励设计**: 摘要未设计显式RL奖励；它用无图像预测与上次图像条件预测是否一致作为证书，决定每一步是否处理图像及解掩码token数；一致则复用先前预测。
- **💡 启发**: 动态检索可用先不检索的预测与检索后预测的一致性或差异作为是否触发检索的证书或门控信号，把检索预算花在真正需要外部信息的步骤。

---

### 可验证结果作为搜索型Agent的奖励来源
在定理证明搜索中，递归Agent进行异步搜索和并行探测，最终由内核检查的证明或反驳标签提供可验证结果；论文指出这些任务也可作为强化学习的奖励。

#### 📄 [Scaling Lean Theorem Proving for Real-World Code Verification](https://huggingface.co/papers/2610.38174)
- **奖励设计**: 摘要显示：Aegis生成的任务每个冻结陈述带内核检查的证明或反驳标签；这些任务可作为强化学习的奖励。EasyProver本身使用现成前沿模型无额外训练，搜索过程包括异步搜索和并行tactic探测。
- **💡 启发**: 对动态检索可构建可验证的最终答案或证据标签作为终端奖励，并用并行检索探测提高覆盖率；但需设计检索步骤的过程奖励，而不是只依赖最终标签。

---

## ⚠️ 现有研究的局限与空白 (Gaps & Contradictions)

当前奖励设计存在稀疏可验证奖励与稠密过程奖励之间的张力：WeFair表明严格验证优于辅助奖励，并警告过度强调后续消费会导致意图漂移；而在线Agent范式依赖LLM-as-a-Judge提供步级稠密奖励，虽改善中间进展评估，却可能引入裁判偏差与奖励黑客风险。动态检索还缺少检索专用的信息增益或证书式奖励公式，LARC与LOWN分别提供信息增益RL和一致性证书门控的思想，但摘要未给出面向多步检索的奖励构造与信用分配方案。另一个空白是可验证奖励在定理证明搜索中较成熟，却尚未迁移到动态检索的何时检索、查询重写、证据覆盖与停止决策；如何联合优化意图保真、信息增益、检索成本与终端可验证正确性，仍缺少统一框架。

## 🚀 Top 3 可立即尝试的行动思路 (Actionable Ideas)

1. **在查询重写与检索门控上先部署WeFair式分层奖励：高权重奖励精确保持用户即时意图或重写目标一致性，消费偏好仅作低权重辅助；用DPO学习相对偏好、GRPO做严格验证，重点监测意图漂移与检索收益。**

2. **为每次检索或重写动作增加LLM-as-a-Judge步级过程奖励，并与终端任务完成奖励联合训练；采用步级优势估计和相似检索状态邻域价值估计，缓解长检索轨迹的credit assignment不稳定问题。**

3. **实现信息增益与一致性证书门控：先让模型无检索预测，再用检索后预测差异或信息增益决定是否检索、检索多少；把信息增益作为内在奖励并与终端可验证奖励做加权或约束，减少无效检索与奖励漂移。**
