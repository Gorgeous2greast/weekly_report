## 💡 跨领域洞察

### Coding Agent评估正从任务完成转向规格、结构与指令遵循的多维验收
SatisFix关注智能体是否在规格满足化后偏离需求，JoyFrontBench用目标导向验收契约区分部分实现与应用成功，ExpertCrowd-SWE用专家撰写多文件任务和加权可执行标准评估陌生代码库，ACF研究则把AGENTS.md等上下文文件中的显式指令操作化为可测量合规性。这些工作共同表明，单一任务分不足以刻画Coding Agent的真实可靠性。

### Memory与harness正在成为可学习、可优化的运行时策略
CoReMem把记忆写入/读取成本内化，并用下一任务上的实测记忆价值指导紧凑记忆与actor适应；EvoX将harness视为运行时策略，通过Action Realization、Execution Continuity和Outcome Grounding补足模型语义决策；AskALCF则把日志诊断与失败归因路由到可执行修复。三者都指向同一趋势：智能体能力不仅来自模型权重，也来自外部状态与运行时控制。

### Agentic RL与自进化系统需要验证门控和成本核算
EvoX引入Contrast评估框架以公平比较不同harness，AskALCF用两阶段充分性检验区分文档缺失与检索缺失，并将失败路由到修复。对于RSI/自进化，本周强信号不足，说明“能自我更新”之外，更关键的是如何验证更新值得保留、如何控制自改进成本与副作用。

## 📚 💻 Coding Agent

### 🌟 强烈推荐

#### [Eliciting and Mitigating Specification Satisficing in Coding Agents](https://arxiv.org/abs/2611.16289)

**作者**: Ruixin Wang, Tianyi Zhang | **发布**: 2026-11-12

*<sub>📊 评分明细: 权威 15 | 相关 29 | 时效 20 | 分类 9 | 热度 8 ➔ **总分: 81**</sub>*

论文识别编码智能体在满足任务规格时会出现“规格满足化”：智能体先考虑过满足需求的实现，后又因自认可理由改选不满足需求的方案。提出SatisFix，引导智能体报告此类选择及理由，并逐项对照任务描述检查；在DeepSWE和SWE-bench Pro上以五个LLM和两个智能体框架评估，SatisFix平均提升base agent pass@1 5.09%和7.06%，在DeepSWE上比最佳基线高3.98%。

**技术亮点**: 让智能体显式报告规格冲突选择及理由，再逐条对照任务描述核验；消融显示报告与检查两步均对提升有贡献。

**落地难度**: Medium

---

#### [CoReMem: Cost-Internalizing Memory for Successive Coding Tasks with Prospective Valuation](https://arxiv.org/abs/2611.17316)

**作者**: Peiwen Li, Harshit Verma, Sophia Zhou et al. | **发布**: 2026-11-12

*<sub>📊 评分明细: 权威 15 | 相关 28 | 时效 20 | 分类 9 | 热度 7 ➔ **总分: 79**</sub>*

论文针对编码智能体在连续任务中需为未知下一任务写记忆、读记忆的问题，提出CoReMem成本内化框架，用下一任务上有无轨迹片段的实测记忆价值指导紧凑记忆设计，以仓库位置和可执行检查为锚点；并做actor适应，在rollout组内估计记忆价值，奖励优先解决并惩罚成功运行步数。ChainSWE上27B actor解决率从21.0%升至25.7%。

**技术亮点**: 前瞻式片段估值、锚点式紧凑记忆、基于provenance-gated value credit的actor适应。

**落地难度**: Medium

---

#### [JoyFrontBench: Evaluating Front-End Coding Agents through Goal-Oriented Acceptance Contracts](https://arxiv.org/abs/2611.14952)

**作者**: Xiaoyi Qiao, Yicheng Wang, Jianan Lin et al. | **发布**: 2026-11-11

*<sub>📊 评分明细: 权威 15 | 相关 28 | 时效 19 | 分类 9 | 热度 7 ➔ **总分: 78**</sub>*

论文指出现有前端编码智能体评估中高任务分可能与核心工作流失败并存，提出JoyFrontBench，用目标导向验收契约区分部分实现与应用成功。每个契约预先定义核心任务和强制标准，核心任务需全部强制标准满足且达共享完成阈值，应用成功需同一运行产物中所有核心任务通过。基准包含100个前端开发问题、764个任务和2596条原子标准，并评估五种编码模型与两种harness。

**技术亮点**: 目标导向验收契约、证据接地判断、确定性记录审计与固定评分规则，同时保留任务级分级评估和应用级验收。

**落地难度**: Medium

  - 💡 用于PR合并前回归测试生成与变更行为保护。

  - 💡 用于Coding Agent监督工具、架构漂移检测与人工审查界面。
- **[Bug Finding With Agentic Symbolic Execution](https://arxiv.org/abs/2611.15596)**: 将符号执行工具CrossHair与AI编码智能体编排，自动插桩断言、合成数据库符号环境并构造可复现测试。
  - 💡 用于Python Web应用自动化缺陷发现与可复现证据生成。
- **[Do They Do as They Are Told? Investigating Coding Agents' Adherence to Explicit Instructions in Context Files](https://arxiv.org/abs/2611.13709)**: 实证研究AGENTS.md等agent context files中显式指令的遵循情况。
  - 💡 用于设计可测试的上下文文件治理规则与智能体合规审计。
- **[ExpertCrowd-SWE: Measuring Frontier Coding Agents on Expert-Authored Engineering Tasks in Unfamiliar Codebases](https://arxiv.org/abs/2611.13246)**: 面向陌生大型代码库的100个专家撰写多文件工程任务基准，评估前沿编码智能体。
  - 💡 用于Coding Agent在真实工程任务上的细粒度验收与部署选型。
- **[Where LLM Agents Get Stuck Debugging Databases: Access More Than Reasoning](https://arxiv.org/abs/2611.17304)**: 对Claude Code诊断8个生产数据库事件的现场观察，指出运行时状态访问是主要瓶颈。
  - 💡 用于设计数据库排障智能体的可观测性接口、只读执行与权限边界。

## 📚 🤖 Agentic RL / 多智能体

### 🌟 强烈推荐

#### [EvoX: Rethinking the Agent Harness as a Runtime Policy](https://arxiv.org/abs/2611.15006)

**作者**: Haoyang Zhang, Qumeng Sun, Xiao Zhang et al. | **发布**: 2026-11-11

*<sub>📊 评分明细: 权威 15 | 相关 26 | 时效 19 | 分类 8 | 热度 7 ➔ **总分: 75**</sub>*

论文针对LLM智能体工具调用不匹配、流程中断和完成声明不受支持等问题，提出EvoX，一个Rust多模型agent runtime，将harness视为补充基础模型语义策略的运行策略，通过Action Realization、Execution Continuity和Outcome Grounding实现确定性运行时控制；并引入Contrast评估框架。在5个基准、6个基础模型和6个harness的691个共同任务-模型对上，EvoX取得56.2%最高数值成功率，比其余五个harness平均高约3.0个百分点。

**技术亮点**: 运行时策略视角、三类互补机制、受控可审计的Contrast评估框架。

**落地难度**: Medium

## 🏆 值得深入阅读的 Top Papers

1. **[Eliciting and Mitigating Specification Satisficing in Coding Agents](https://arxiv.org/abs/2611.16289)**
   > 本周最高分Coding Agent论文，识别出智能体自认可但不满足任务规格的“规格满足化”失败模式，并提出可落地的SatisFix流程。其在DeepSWE和SWE-bench Pro上以多种LLM与agent框架验证，pass@1提升明确。

2. **[CoReMem: Cost-Internalizing Memory for Successive Coding Tasks with Prospective Valuation](https://arxiv.org/abs/2611.17316)**
   > 将连续编码任务中的记忆写入/读取成本显式内化，并用下一任务上的实测记忆价值指导记忆设计与actor适应。在ChainSWE上提升27B actor解决率，对Coding Agent长期记忆与成本控制有直接启发。

3. **[JoyFrontBench: Evaluating Front-End Coding Agents through Goal-Oriented Acceptance Contracts](https://arxiv.org/abs/2611.14952)**
   > 提出目标导向验收契约，区分部分实现与应用成功，避免高任务分掩盖核心工作流失败。基准规模较大，包含100个问题、764个任务和2,596条原子标准，并评估多种模型与harness。

4. **[ADAPT: Agentic Diff-Aware Patch Testing for Pull Requests](https://arxiv.org/abs/2611.16114)**
   > 聚焦PR变更行为保护，用diff感知的测试生成与fail-to-pass验证迭代修正。方法贴近真实软件工程流程，适合用于合并前回归测试生成。

5. **[Rasoi: Visual Diffs for Evaluating Structural Changes Made by Coding Agents](https://arxiv.org/abs/2611.16293)**
   > 从人机协作与监督角度研究Coding Agent造成的架构变化，用可视化diff帮助开发者发现意外重构和范围外修改。其一周12名开发者研究提供了真实使用证据。

6. **[Bug Finding With Agentic Symbolic Execution](https://arxiv.org/abs/2611.15596)**
   > 将符号执行与编码智能体结合，自动插桩断言、合成数据库符号环境并生成可复现测试。在百万行级Python Web应用上报告了执行覆盖率提升与大量可复现bug。

7. **[Do They Do as They Are Told? Investigating Coding Agents' Adherence to Explicit Instructions in Context Files](https://arxiv.org/abs/2611.13709)**
   > 首次系统评估AGENTS.md等上下文文件中显式指令是否被真正执行，将指令操作化为可测量脚本。研究发现遵循率在指令类别和智能体间分化，对Coding Agent治理有直接价值。

8. **[ExpertCrowd-SWE: Measuring Frontier Coding Agents on Expert-Authored Engineering Tasks in Unfamiliar Codebases](https://arxiv.org/abs/2611.13246)**
   > 提供100个专家撰写、多文件、陌生代码库的工程任务基准，配密封参考解和加权可执行评分器。任务跨87个项目、11种语言，并评估七个前沿模型共3,495次运行，适合作为Coding Agent真实工程能力评测。

9. **[Where LLM Agents Get Stuck Debugging Databases: Access More Than Reasoning](https://arxiv.org/abs/2611.17304)**
   > 基于生产数据库事件的现场观察，指出运行时状态访问而非单纯推理是数据库排障智能体的主要瓶颈。结论对可观测性接口、只读执行和权限设计有实践指导意义。

10. **[AskALCF: A Self-Improving Agentic System for Intelligent HPC User Support](https://arxiv.org/abs/2611.15700)**
   > 面向部署后的智能体支持系统，将失败归因到知识、检索、提示、模型行为或工具执行，并路由到修复。虽属弱RSI，但其诊断-修复闭环和2,174个真实支持turn上的失败归因结果具有参考价值。

11. **[EvoX: Rethinking the Agent Harness as a Runtime Policy](https://arxiv.org/abs/2611.15006)**
   > 将agent harness作为运行时策略，通过Action Realization、Execution Continuity和Outcome Grounding提升工具型智能体执行可靠性。其Contrast评估框架和跨5基准、6模型、6harness的比较增强了结论可信度。

12. **[Spec-Driven PBT: Deriving Semantic Invariants from Code Specifications for Agentic Property-based Testing](https://arxiv.org/abs/2611.15920)**
   > 提出从规格而非实现推导属性测试不变量，降低实现偏置。对agentic coding中的PRD驱动测试和规格遵循验证具有方法启发。
