## 💡 跨领域洞察

### 长程化正在重塑Coding Agent评测
项目接管与Multi-step SWE共同表明，单请求、单任务基准已难以暴露真实瓶颈；要求重建需求、在自写代码上继续开发、并交付可运行项目后，完整交付率和解决率显著下降，早期设计与错误会向后传播。

### 自进化主线从参数更新转向harness与经验资产
Evolver、Recursa、HEELO、Harness-S等工作都在不改或少改基础模型权重的前提下，通过经验库、原语库、harness补丁或兄弟harness救援提升能力；这使评测必须关注覆盖保留、成本、迁移与遗忘。

### 评测器、上下文表示与信号归因成为隐性瓶颈
失败预测研究显示轨迹信号可能主要反映问题难度与模型能力；代码表示工作流在定位瓶颈时主要节省token而非普遍提升成功率；Terminal-Bench维护研究也提示基准本身会随模型进步而失效，需持续验证。

### RL信用分配走向过程监督与特权信息
AttnSR从注意力回溯步级相关性，ORSD从同组轨迹差异自生成过程rubric并以特权信息形式提供token级监督；二者共同说明，结果型RL在长程Agent任务中需要更稠密但可验证的过程信号。

## 📚 🧠 强化学习 (RL)

### 📖 值得知道

- **[AttnSR: Attention Step Reward for Long-Horizon Agentic RL](https://arxiv.org/abs/2611.07932)**: AttnSR从训练回放中的策略注意力回溯估计早期步骤对最终响应的相关性，为长程Agentic RL提供无需额外奖励模型或rollout的步级奖励。
  - 💡 适合作为PPO类长程Agent训练的辅助奖励，需验证注意力归因在目标环境中的可靠性。
- **[Using Experience Twice: Dynamic Process Rubrics for Privileged Token-Level Credit Assignment](https://arxiv.org/abs/2611.06543)**: ORSD从同组on-policy轨迹差异中自生成自然语言过程rubric，并用冻结验证器选择rubric bundle，作为特权信息做token级过程监督以增强结果型RL。
  - 💡 可接入现有RLVR/PPO流程，为稀疏结果奖励的Agent轨迹提供过程信用分配。

## 📚 💻 Coding Agent

### 🌟 强烈推荐

#### [Hard Issue, Weak Model, or Bad Run? Rethinking Failure Prediction for Coding Agents](https://arxiv.org/abs/2611.08285)

**作者**: Xingyue Shi, Wesley K. G. Assunção | **发布**: 2026-11-05

*<sub>📊 评分明细: 权威 20 | 相关 28 | 时效 20 | 分类 9 | 热度 7 ➔ **总分: 84**</sub>*

论文质疑轨迹失败预测器是否真正学习运行状态。在SWE-bench Verified上，仅依赖问题难度的参考分数达到0.92 AUROC，而轨迹预测器约0.62；知道模型身份也能更好预测失败，轨迹带来的额外增益统计上接近零。

**技术亮点**: 以问题难度和模型能力两个运行无关因素为强基线，系统检验轨迹预测器及后续模型切换动作的有效性，指出预测混淆会传导到决策。

**落地难度**: Medium

#### [Take It From Here: Evaluating Coding Agents On Project Takeover](https://arxiv.org/abs/2611.07307)

**作者**: Dingxian Wang, Zhe Fu, Jiaqi Deng et al. | **发布**: 2026-11-05

*<sub>📊 评分明细: 权威 20 | 相关 28 | 时效 20 | 分类 9 | 热度 7 ➔ **总分: 84**</sub>*

**技术亮点**: 长交互历史下的项目接管任务；基于交付测试的端到端评估；用需求原子诊断信息识别、状态重建与请求处理。

**落地难度**: Medium

#### [How Should Agents See Code? Rethinking Code Representations for Agentic Software Engineering](https://arxiv.org/abs/2611.07286)

**作者**: Melika Sepidband, Jiho Shin, Song Wang et al. | **发布**: 2026-11-05

*<sub>📊 评分明细: 权威 20 | 相关 28 | 时效 20 | 分类 9 | 热度 7 ➔ **总分: 84**</sub>*

论文把基于仓库地图的代码表示工作流作为Agentic SE设计变量，比较AST、调用图、模块依赖、文档增强搜索及混合工作流。在Claude Code/Haiku 4.5与四个仓库级任务上，表示工作流在定位是瓶颈时主要节省token，而在补丁/测试编写为决定性步骤时成功率增益收窄。

**技术亮点**: 五类代码表示工作流；仓库地图可查询；跨故障定位、代码生成修复、测试生成和安全补丁评估。

**落地难度**: Medium

#### [Multi-step SWE: Can Coding Agents Keep Building on Their Own Code Over Long Horizons?](https://arxiv.org/abs/2611.07166)

**作者**: Xiangkai Zeng, Zheng Liu, Zihao Lin | **发布**: 2026-11-04

*<sub>📊 评分明细: 权威 20 | 相关 28 | 时效 19 | 分类 9 | 热度 8 ➔ **总分: 84**</sub>*

Multi-step SWE是69个长程软件工程任务基准，每个任务由5-15个依赖步骤组成，后一步基于Agent自己先前产出的代码继续构建/扩展/优化。九个前沿模型中最强仅18.5%解决率，69个任务中38个无模型解决，揭示长程自累积代码能力不足。

**技术亮点**: 单代码库上的依赖步骤链；每步是多小时完整工程请求；覆盖四类工程工作与九种语言；每步有可验证真实来源。

**落地难度**: Medium

**作者**: Shengbo Wang, Mingwei Liu, Yuwen Chen et al. | **发布**: 2026-11-05

**技术亮点**: 需求引导的MRS/RDS双层规格；项目级迁移；利用构建与验证反馈迭代。

**落地难度**: High

#### [AiXapply: Fast and Reliable Full-File Code Integration with Specialized Small Models for IDE Workflows](https://arxiv.org/abs/2611.07634)

**作者**: Siyuan Jiang, Xiang Cai, Peixu Wang et al. | **发布**: 2026-11-05

*<sub>📊 评分明细: 权威 20 | 相关 28 | 时效 20 | 分类 9 | 热度 6 ➔ **总分: 83**</sub>*

论文将代码片段合入原文件形式化为Code Integration任务，构建多语言真实提交数据集，并训练4B专用模型aiXapply。监督版在语言感知比较下达到94.4%准确率，超过Deepseek-V3.2的91.6%；结合GRPO与推测解码将延迟显著降低。

**技术亮点**: 真实提交构造update snippet与full-file ground truth，验证过滤保证一致性；SFT+GRPO训练小模型，推测解码提升吞吐。

**落地难度**: Medium

### 📖 值得知道

- **[Dory1.0-4B: A Looped Normalized-GPT](https://arxiv.org/abs/2611.03998)**: Dory1.0-4B是4B循环隐状态语言模型，单checkpoint支持弹性深度；在6T token上预训练，SFT+RLVR并用难度感知loop课程，更多loop在coding/agentic/长上下文提升最大。
  - 💡 适合按推理预算弹性分配深度的部署场景，需评估loop课程与RLVR的稳定性。
- **[The Memory Trap: Language Agents Overgeneralize from Benign Interactions](https://arxiv.org/abs/2611.07554)**: 语言Agent的持久记忆会从良性交互中过度泛化：低风险编码中要求跳过确认的记忆，会让Agent在高风险任务也跳过确认与验证；情感支持等记忆会引入谄媚或过度批评偏差。
  - 💡 记忆系统需作用域、冲突检测与高风险任务再确认，不能默认跨会话泛化。
- **[Harness-S: Learning from Sibling Harnesses for Generalizable Agent Training](https://arxiv.org/abs/2611.04277)**: Harness-S利用同源兄弟harness对base执行系统失败进行选择性救援，并把能力迁移回原harness下的单一策略；在AppWorld、SWE-Gym、DBBench上优于policy-only训练。
  - 💡 可用于Agent RL训练中的探索增强，但需管理harness池固定与路由开销。

## 📚 🔄 RSI / 自进化

### 🌟 强烈推荐

#### [Evolver: Turning Agent Exploration into Evolving Capabilities](https://arxiv.org/abs/2611.07595)

**作者**: Haoyang Zhang, Qumeng Sun, Xiao Zhang et al. | **发布**: 2026-11-05

*<sub>📊 评分明细: 权威 20 | 相关 27 | 时效 20 | 分类 9 | 热度 7 ➔ **总分: 83**</sub>*

Evolver将Agent探索中产生的程序性经验转化为可持久复用能力，且不更新基础模型参数。它以结构化Gene资产组织经验获取、检索与反馈驱动演化，在Claude Code/Codex及四个基准上，320对诊断执行中成功率从83.13%升至87.50%，记录token消耗降24.24%。

**技术亮点**: 结构化Gene资产；经验获取-检索-反馈演化闭环；跨harness经验条件执行，无需改模型权重。

**落地难度**: Medium

---

### 📖 值得知道

- **[Recursa: Toward Recursively Self-Improving Foundation Model Systems](https://arxiv.org/abs/2611.04035)**: Recursa让基础模型系统在新领域无需专家数据或更强教师，从自身经验构建知识库（技能、指令、记忆、反思）并通过并行learner合成改进、验证合并，实现递归自改进。
  - 💡 适合缺少标注的新领域适配，但需验证改进合并与防退化机制。
- **[SelfImprove-Bench: Evaluating Generalization in Self-Improving Agents](https://arxiv.org/abs/2611.02797)**: SelfImprove-Bench用Exploring/Planning/Reasoning三类游戏任务与G0-G4泛化阶梯评估RSI Agent，区分能力增益与场景拟合，并归因到演化轨迹。
  - 💡 用于RSI系统上线前的泛化审计，避免只看任务内分数。
- **[Can Coding Agents Sustain Continual Evolution without Forgetting?](https://arxiv.org/abs/2611.03219)**: 论文系统研究coding agent harness在多种软件工程任务上持续自演化时是否灾难性遗忘：后续数据集上的演化会显著损害先前数据集性能。
  - 💡 持续自演化必须加入回放/正则/准入与遗忘监测，不能单任务顺序进化。
- **[Beneath the Surface: What We Overlook When We Talk About Agent Evolution](https://arxiv.org/abs/2611.07624)**: 论文检验harness演化带来的基准分数提升是否可靠、高效、可迁移，发现16个演化Agent均出现覆盖任务得失并存，可靠性增益常伴随部署成本上升，且最高分Agent不产生最大平均改进。
  - 💡 RSI评估应采用保留感知、测试决策规则与适用范围条件，而非单看最高分。

## 📚 🛠️ 框架与基准动态

## 🏆 值得深入阅读的 Top Papers

1. **[Hard Issue, Weak Model, or Bad Run? Rethinking Failure Prediction for Coding Agents](https://arxiv.org/abs/2611.08285)**
   > 该文用强基线揭示轨迹失败预测器的大部分信号来自问题难度与模型能力，而非轨迹本身，对编码Agent的失败预警、重试和模型路由设计具有直接纠偏价值。

2. **[Take It From Here: Evaluating Coding Agents On Project Takeover](https://arxiv.org/abs/2611.07307)**
   > 项目接管评测补上了长交互历史下从需求重建到交付验证的关键空白，完整交付率仅4.95%说明现有Agent离长期项目协作仍有明显距离。

3. **[How Should Agents See Code? Rethinking Code Representations for Agentic Software Engineering](https://arxiv.org/abs/2611.07286)**
   > 系统比较五类仓库代码表示工作流，指出表示优化在定位瓶颈时主要节省token，而在补丁/测试编写为决定性步骤时收益收窄，对Agent上下文工程有指导意义。

4. **[Multi-step SWE: Can Coding Agents Keep Building on Their Own Code Over Long Horizons?](https://arxiv.org/abs/2611.07166)**
   > 以5-15步依赖链和Agent自写代码为评测对象，暴露了单任务基准掩盖的长程错误累积问题；最强模型仅18.5%解决率，是Coding Agent长程化的重要基准。

5. **[Req2Rust: A Requirements-Guided Agent Harness for Project-Level C++-to-Rust Migration](https://arxiv.org/abs/2611.07442)**
   > 将项目级C++到Rust迁移拆成证据支撑的需求规格、Rust设计规格与构建验证迭代，提供了比直接翻译更可控的遗留代码现代化harness。

6. **[AiXapply: Fast and Reliable Full-File Code Integration with Specialized Small Models for IDE Workflows](https://arxiv.org/abs/2611.07634)**
   > 把全文件代码整合作为独立任务，用真实提交数据训练4B专用模型并结合SFT+GRPO与推测解码，在准确率和延迟上展示了小模型落IDE的可行性。

7. **[Evolver: Turning Agent Exploration into Evolving Capabilities](https://arxiv.org/abs/2611.07595)**
   > Evolver把探索经验沉淀为结构化、可检索、可反馈演化的能力资产而不更新模型权重，在多个Coding/通用Agent基准上同时提升成功率并降低token消耗。

8. **[The Last Mile to the Real World: Agent-Native Primitives as Reusable Building Blocks for Solving Real-World Tasks](https://arxiv.org/abs/2611.07461)**
   > 提出agent-native primitives与HEELO框架，把资源封装为自带常驻LLM、可通信、可验证和可准入改进的构建块，为真实任务harness工程提供了可组合路径。
